lo1 runs on macOS, Linux and Windows. On Windows, run it from PowerShell with Docker Desktop.

You can run it inside [WSL 2](https://learn.microsoft.com/windows/wsl/install) instead, with Docker
Desktop's WSL integration turned on for your distribution. lo1 then updates the hosts file and
trusts its certificate authority inside Linux, so a browser on Windows won't find the workspace's
domains or trust its certificates.

## Prerequisites

| Dependency                                    | Version | Purpose                                           |
| --------------------------------------------- | ------- | ------------------------------------------------- |
| [Node.js](https://nodejs.org/)                | 24+     | CLI runtime                                       |
| [Docker](https://docs.docker.com/get-docker/) | 20.10+  | Container services, infrastructure, reverse proxy |
| [Git](https://git-scm.com/)                   | 2.x     | Cloning repositories with `lo1 init`              |

Docker Compose v2 ships with Docker Desktop on macOS and Windows, and with current Docker Engine
packages on Linux.

On Linux, install `certutil` too if you use TLS. Chrome and Firefox don't read the system
certificate store, so `lo1 up` uses `certutil` to add its local certificate authority to theirs.
Without it, they show "Your connection is not private" for every service.

```bash
sudo apt install libnss3-tools   # Debian, Ubuntu
sudo dnf install nss-tools       # Fedora
sudo pacman -S nss               # Arch
```

## Install the CLI

You can install lo1 with npm, pnpm, Yarn or Bun, but Node.js is still needed: the `lo1` command
runs on Node whichever package manager installed it.

<Tabs items={['npm', 'pnpm', 'Yarn', 'Bun']}>
  <Tab value="npm">
    ```bash
    npm install -g @lo1/cli
    ```
  </Tab>
  <Tab value="pnpm">
    ```bash
    pnpm add -g @lo1/cli
    ```
  </Tab>
  <Tab value="Yarn">
    ```bash
    yarn global add @lo1/cli
    ```
  </Tab>
  <Tab value="Bun">
    ```bash
    bun install -g @lo1/cli
    ```
  </Tab>
</Tabs>

Check that it is on your path:

```bash
lo1 --help
```

Then check that Docker, Compose and Git are ready:

```bash
lo1 doctor
```

Run it again from a workspace to also check its `lo1.yaml`, the ports it needs and its hosts file
entries.

## Editor support

The `@lo1/sdk` package publishes a JSON Schema for `lo1.yaml`. Point the YAML language server at it
for autocompletion and validation:

```yaml title="lo1.yaml"
# yaml-language-server: $schema=https://unpkg.com/@lo1/sdk/schemas/lo1.v1.schema.json
version: "1"
```
